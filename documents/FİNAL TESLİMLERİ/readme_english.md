# RedRose RAG AI Knowledge Assistant 🌹🤖

Developed for RedRose Technology, this project is a RAG (Retrieval-Augmented Generation) assistant that allows users to perform semantic searches on uploaded documents (PDF, DOCX, TXT) and receive AI-powered, hallucination-free (strict-context) answers based purely on the contents of these documents.

## 🚀 Tech Stack

**Backend:**
* FastAPI (Asynchronous RESTful API)
* PostgreSQL & pgvector (Vector Database)
* SQLAlchemy 2.0 & Pydantic (ORM and Data Validation)
* LangChain & OpenAI API (AI Orchestration)
* Models: `text-embedding-3-small`, `gpt-4o-mini`

**Frontend:**
* Next.js (React Framework)
* Node.js / npm

## 🔒 Data Privacy and Security

Data security was heavily prioritized during the system design:
* **No Physical File Hosting:** Uploaded original documents are not granted public access. Files are only read in memory (RAM) and are never physically hosted on the server.
* **No Sensitive Logging:** Document contents and processed text chunks are kept secret and are never printed or saved in server logs.
* **Limited Third-Party Transmission:** Original files are not sent to OpenAI. Only the text chunks generated by the system are securely transmitted to the OpenAI API for embedding and generation processes. Model creativity (`temperature=0.0`) is restricted to prevent hallucination.

## ⚙️ Installation and Execution Guide

To run the application at full capacity, both the Backend and Frontend systems must be up and running.

### Prerequisites
* Python 3.10+
* Node.js v18.x+
* PostgreSQL with the `pgvector` extension installed
* A valid OpenAI API Key

### 1. Backend (FastAPI) Setup

Clone the project and navigate to the root directory:
```bash
git clone https://github.com/your_username/RedRose-RAG-Assistant.git
cd RedRose-RAG-Assistant
```

Create and activate a virtual environment:
```bash
# For Windows
python -m venv venv
.\venv\Scripts\activate

# For macOS/Linux
python3 -m venv venv
source venv/bin/activate
```

Install the required Python packages:
```bash
pip install -r requirements.txt
```

Create a `.env` file in the root directory and add your credentials:
```env
OPENAI_API_KEY="sk-proj-your-api-key-here"
DATABASE_URL="postgresql://username:password@localhost:5432/database_name"
```

Ensure the `pgvector` extension is enabled in your database:
```sql
CREATE EXTENSION IF NOT EXISTS vector;
```

Start the backend server:
```bash
uvicorn main:app --reload
```
*(The Backend API will start running at http://localhost:8000. You can access the Swagger UI at http://localhost:8000/docs.)*

### 2. Frontend (Next.js) Setup

Open a new terminal tab and navigate to your frontend directory (e.g., `frontend`):
```bash
cd frontend
```

Install the required npm packages:
```bash
npm install
```

Create a `.env.local` file in the frontend directory and define the API URL:
```env
NEXT_PUBLIC_API_URL=http://localhost:8000
```

Start the frontend development server:
```bash
npm run dev
```
*(The user interface will start running at http://localhost:3000.)*

## 📡 API Endpoints

| **Method** | **Endpoint** | **Description** |
| :--- | :--- | :--- |
| `GET` | `/documents/` | Returns a list of all uploaded documents. |
| `GET` | `/documents/{id}` | Returns the header information and chunk list of a specific document. |
| `POST` | `/documents/` | Uploads, vectorizes, and saves a new document (.pdf, .docx, .txt). |
| `POST` | `/search/` | Performs a vector search for the user query and returns the closest text chunks without LLM costs. |
| `POST` | `/ask/` | Executes a RAG query. Finds the most relevant documents for the question and generates a contextual answer in natural language using the GPT model. |
| `DELETE` | `/documents/{id}` | Permanently deletes the specified document and all its text chunks from the database. |
